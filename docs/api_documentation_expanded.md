# API Documentation

## Overview

SpaceCDF exposes a JSON REST API and a WebSocket channel for
real-time concurrent-design collaboration. This document is the
authoritative reference for engineers integrating SpaceCDF with
external tools, building automation, or extending the platform.

| Property | Value |
|----------|-------|
| Base URL (default) | `http://localhost:8000/api` |
| Content type | `application/json; charset=utf-8` |
| Authentication | Bearer token (Authorization header) — see §Auth |
| Total endpoints | 105+ |
| WebSocket path | `/ws/session/{session_id}` |
| OpenAPI spec | `/openapi.json` |
| Interactive docs | `/docs` (Swagger), `/redoc` |

> **Standard reference.** SpaceCDF follows REST conventions consistent
> with the Microsoft API Guidelines —
> [https://github.com/microsoft/api-guidelines](https://github.com/microsoft/api-guidelines).
> The OpenAPI specification is generated by FastAPI —
> [https://fastapi.tiangolo.com/](https://fastapi.tiangolo.com/).

## Authentication

All endpoints (except `/health` and `/openapi.json`) require a
Bearer token:

```http
GET /api/studies/abc123 HTTP/1.1
Host: cdf.example.org
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpX...
Content-Type: application/json
```

| Scope | Permission |
|-------|------------|
| `read` | GET on studies, sessions, positions, KB |
| `write` | POST/PUT/PATCH on studies, sessions, parameters |
| `admin` | DELETE, parametric data edit, equipment DB import |
| `instructor` | Create cohort sessions, view all teams' studies |

Tokens are issued by the auth provider configured in
`packages/spacecdf-server/src/spacecdf_server/auth.py`. In
classroom mode, instructors create tokens via the **Cohort** tab.

## Conventions

### HTTP status codes

| Code | Meaning | Typical cause |
|------|---------|---------------|
| 200 | OK | Successful GET / PATCH |
| 201 | Created | Successful POST |
| 204 | No Content | Successful DELETE |
| 400 | Bad Request | Invalid request body or query params |
| 401 | Unauthorized | Missing or invalid token |
| 403 | Forbidden | Token valid but lacks required scope |
| 404 | Not Found | Resource ID unknown |
| 409 | Conflict | Stale state — re-run design before retry |
| 422 | Unprocessable Entity | Schema validation failed (Pydantic) |
| 429 | Too Many Requests | Rate limit hit |
| 500 | Internal Server Error | Bug — file a GitHub issue with `request_id` |

### Pagination

Collection endpoints accept `limit` and `cursor` query parameters
and return a `next_cursor` field in the response:

```json
{
  "items": [...],
  "next_cursor": "eyJpZCI6MTIzfQ"
}
```

Default limit 50, maximum 200.

### Rate limits

| Class | Per-token quota | Per-IP quota |
|-------|-----------------|--------------|
| Read | 600 / min | 1200 / min |
| Write | 120 / min | 240 / min |
| Optimizer / sensitivity | 10 / min | 20 / min |

`429` responses include `Retry-After` (seconds) and
`X-RateLimit-Reset` (epoch).

### Error envelope

```json
{
  "code": "E_BUD_022",
  "message": "Mass margin violated.",
  "details": {
    "subsystem": "payload",
    "actual_margin_pct": 4.1,
    "required_margin_pct": 10.0
  },
  "request_id": "req_01HF…"
}
```

## Core design

### `POST /design/quick-design`

Run the full design loop (20 agents, convergence in seconds).

**Request body:**

```json
{
  "requirements": {
    "name": "EOSAT-1",
    "mission_type": "earth_observation",
    "spacecraft_class": "nano",
    "orbit": { "orbit_type": "sso", "altitude_km": 450, "inclination_deg": 98.0 },
    "payloads": [
      { "name": "Multispectral Imager", "mass_kg": 1.5, "power_w": 8, "data_rate_mbps": 100 }
    ],
    "design_lifetime_years": 3
  }
}
```

**Response (200):**

```json
{
  "converged": true,
  "iterations": 7,
  "total_time_s": 1.43,
  "parameters": {
    "battery_capacity_wh":  { "value": 24.0,  "unit": "Wh" },
    "solar_array_area_m2":  { "value": 0.32,  "unit": "m^2" },
    "antenna_gain_dbi":     { "value": 4.0,   "unit": "dBi" }
  },
  "budgets": { "mass_kg": 6.4, "power_w": 12.7, "link_margin_db": 5.6 },
  "warnings": [],
  "conflicts": []
}
```

### `POST /studies/`

Create a study. Persists requirements + mission need for later
reference.

### `GET /studies/{id}`

Retrieve study state. Returns the same shape as `quick-design`
plus a `created_at` and `updated_at`.

## Lifecycle services

### `POST /lifecycle/orbit-trade`

Compute orbit trade study with scored candidates.

**Request:**

```json
{
  "target_gsd_m": 5.0,
  "target_revisit_days": 3,
  "target_latitude_band": "polar",
  "aperture_m": 0.15,
  "max_cost_meur": 50,
  "min_lifetime_years": 5,
  "mission_type": "earth_observation"
}
```

**Response:**

```json
{
  "candidates": [
    {
      "name": "SSO 600 km — 10:30 LTAN",
      "altitude_km": 600,
      "inclination_deg": 97.79,
      "achievable_gsd_m": 4.3,
      "revisit_days": 3.1,
      "natural_lifetime_years": 12.0,
      "total_score": 0.91,
      "rank": 1
    }
  ]
}
```

### `POST /lifecycle/class-advisor`

Recommend spacecraft class from performance / programmatic targets.

### `POST /lifecycle/mission-trade`

Evaluate space vs non-space alternatives. Filtered by
`mission_type`; includes constellation option when economics suggest.

### `GET /lifecycle/spectrum/bands`

Available frequency bands filtered by mission type and licence type.

**Query params:** `mission_type`, `license_type`
(`amateur` / `experimental` / `commercial`), `data_rate_mbps`.

### `POST /lifecycle/spectrum/itu-api-template`

Generate ITU Advance Publication Information filing template.

### `POST /lifecycle/spectrum/iaru-template`

Generate IARU amateur coordination request template.

### `POST /lifecycle/regulatory/rsssa`

Generate Canadian RSSSA filing template.

### `POST /lifecycle/regulatory/export-assessment`

Generate export-control classification assessment.

### `POST /lifecycle/regulatory/copuos-registration`

Generate UN Registration Convention Article IV template.

### `POST /lifecycle/regulatory/eol-report`

Generate end-of-life analysis report (consistent with IADC 25-yr
rule).

### `GET /lifecycle/parametric-data`

Return all parametric model data (mass fractions, cost fractions,
power duty cycles, SA power tables) with source citations.

### `POST /lifecycle/duty-cycles`

Estimate power duty cycles for a mission configuration.

**Request:** `{ spacecraft_class, mission_type, comms_band, eclipse_fraction }`.

### `GET /lifecycle/consistency/{study_id}`

Run full design consistency check. Returns health score, issues by
category.

### `POST /lifecycle/trade-study`

Run a tabular trade study with criteria, weightings, and options.

```json
{
  "name": "Comms band trade",
  "criteria": [
    { "id": "data_rate",  "name": "Data rate",  "weight": 4, "direction": "max" },
    { "id": "license_complexity", "name": "Licence complexity", "weight": 2, "direction": "min" }
  ],
  "options": [
    { "id": "uhf", "name": "UHF amateur", "scores": { "data_rate": 1, "license_complexity": 1 } },
    { "id": "s",   "name": "S-band",      "scores": { "data_rate": 4, "license_complexity": 3 } }
  ]
}
```

### `GET /lifecycle/trade-templates`

List pre-built trade-study templates (orbit, component, ground,
architecture).

### `POST /lifecycle/constellation/design`

Design Walker-delta constellation for coverage targets.

### `GET /lifecycle/beyond-leo/orbits`

List beyond-LEO orbit options (MEO, GEO, HEO, lunar, interplanetary)
with environment data.

### `POST /lifecycle/beyond-leo/transfer`

Compute transfer orbit Δv from LEO to target orbit.

### `POST /lifecycle/beyond-leo/dsn-link`

Compute deep-space link budget for DSN communication.

### `GET /lifecycle/requirements/generate/{study_id}`

Generate SMART requirements from study objectives and functions.

### `POST /lifecycle/requirements/validate`

Validate a requirement against SMART criteria.

### `POST /lifecycle/requirements/check-compliance`

Check non-compliance and get resolution options.

### `GET /engineering/equipment/{domain}/search`

**Domains:** `power`, `aocs`, `link`, `propulsion`, `structure`,
`data`, `thermal`, `integration`.

### `GET /engineering/equipment/needs/{study_id}`

Determine which equipment categories are needed based on
requirements.

### `POST /engineering/equipment/check-compatibility`

Check RF compatibility between transponder and antenna.

### `POST /engineering/equipment/budget-impact`

Compute live budget impact of current equipment selections.

### `GET /engineering/verification`

Run requirement verification against current design state.

### `GET /engineering/cost`

Get cost estimate for current design.

### `POST /engineering/analysis/sensitivity`

Run parametric sensitivity sweep (Morris screening).

### `GET /engineering/analysis/eol-curves`

Get end-of-life degradation curves.

### `POST /engineering/analysis/trade-study`

Run equipment-level trade study.

### `POST /engineering/impact-preview`

Preview downstream impact of parameter changes (dry run — no
execution).

### `GET /optimize/config`

Get available objectives and design variables (filtered by
`mission_type` if provided).

**Query params:** `mission_type`, `has_propulsion`,
`pointing_accuracy_deg`.

### `POST /optimize/sessions/{session_id}`

### `GET /optimize/runs/{run_id}`

Get optimisation run status and results.

### `POST /optimize/sensitivity/{session_id}`

## Sessions (concurrent design)

### `POST /sessions/`

Create a new design session.

### `GET /sessions/{id}`

Get session state.

### `GET /sessions/{id}/history`

Get edit history for a session.

### `WS /ws/session/{session_id}`

Real-time collaboration WebSocket. Message types:

| Type | Direction | Payload |
|------|-----------|---------|
| `parameter_update` | client → server | `{ parameter, value, position }` |
| `state_update` | server → all | full design state diff |
| `convergence_complete` | server → all | iterations, time, conflicts |
| `participant_joined` | server → all | display name + position |
| `participant_left` | server → all | display name |
| `chat` | client ↔ server | low-priority position chat |

### `GET /positions/`

List all engineering positions with roles and key questions.

### `GET /positions/{id}/guidance`

Get computed guidance for a position based on the current design.

### `POST /positions/answers`

Save a position-question answer.

### `GET /positions/answers`

Get all saved position answers.

## Per-resource schemas (selected)

### `Study`

| Field | Type | Required | Notes |
|-------|------|:-------:|-------|
| `id` | string | ✓ | Server-assigned |
| `name` | string | ✓ | ≤ 80 chars |
| `mission_type` | enum | ✓ | `earth_observation` · `comms` · `science` · `tech_demo` · `pnt` · `defence` |
| `spacecraft_class` | enum | ✓ | `nano` · `micro` · `small` · `medium` · `large` |
| `orbit` | `Orbit` | ✓ | See below |
| `payloads` | `Payload[]` | ✓ | At least one |
| `design_lifetime_years` | number | — | default 3 |
| `created_at` | string (ISO 8601) | ✓ | UTC |
| `updated_at` | string (ISO 8601) | ✓ | UTC |

### `Orbit`

| Field | Type | Required | Notes |
|-------|------|:-------:|-------|
| `orbit_type` | enum | ✓ | `leo` · `sso` · `meo` · `geo` · `heo` · `lunar` |
| `altitude_km` | number | ✓ | for `leo`/`sso` |
| `inclination_deg` | number | ✓ | 0 – 180 |
| `raan_deg` | number | — | default auto |

### `Payload`

| Field | Type | Required | Notes |
|-------|------|:-------:|-------|
| `name` | string | ✓ | |
| `mass_kg` | number | ✓ | |
| `power_w` | number | ✓ | average |
| `peak_power_w` | number | — | default = `power_w` |
| `data_rate_mbps` | number | ✓ | average |
| `aperture_m` | number | — | required for optical |

(Other resource schemas: `Requirement`, `LinkBudget`,
`TradeStudy`, `RiskItem`, `Equipment`, `OptimizerRun`,
`SensitivityRun` — see `/openapi.json`.)

## SDK compatibility

| SDK | Version | Status |
|-----|---------|--------|
| Python `spacecdf-client` | 0.4.x | Stable |
| TypeScript `@spacecdf/client` | 0.3.x | Beta |
| OpenAPI generators | — | Use `openapi.json` directly |
| Postman collection | — | Live at `/postman.json` |

Python example:

```python
from spacecdf_client import Client
c = Client("http://localhost:8000", token="…")
result = c.design.quick_design({
    "requirements": {
        "name": "Demo", "mission_type": "earth_observation",
        "spacecraft_class": "nano",
        "orbit": {"orbit_type": "sso", "altitude_km": 450, "inclination_deg": 98.0},
        "payloads": [{"name": "Imager", "mass_kg": 1.5, "power_w": 8, "data_rate_mbps": 100}]
    }
})
print(result["budgets"])
```
